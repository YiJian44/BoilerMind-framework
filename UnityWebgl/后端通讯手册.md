# 锅炉数字孪生 — 后端通讯手册

> 面向后端/接入开发者：说明如何通过 REST API 与 WebSocket 向 Unity 前端推送数据，以及企业微信的多机器人推送与网页配置。
> 所有示例均为可移植命令，不含本地绝对路径。

---

## 一、总体架构

```
后端 / 外部系统（预测模型、监控系统）
  │
  ├── REST API (HTTP POST/GET)  → 端口 8770
  │     POST /api/state        工况状态
  │     POST /api/chart        图表数据
  │     POST /api/focus        场景焦点切换
  │     POST /api/gauge        仪表盘数据
  │     POST /api/fault        故障指令
  │     POST /api/question     问题推送（操作确认/通知）
  │     POST /api/simulate     锅炉模拟计算（前端→后端）
  │     POST /api/calculate_target  目标蒸汽量计算（前端→后端）
  │     POST /api/notify/file      截图/CSV 推送企业微信
  │     POST /api/wechat/config   企业微信机器人配置（网页保存）
  │     POST /api/wechat/test       企业微信测试推送
  │
  │  GET  /api/state    /api/history    /api/health
  │  GET  /api/chart   /api/chart/history
  │  GET  /api/wechat/config
  │  GET  /wechat-config（HTML 配置页）
  │
  └── WebSocket 广播 (ws://host:8770/ws)
         └─► 前端 unity-bridge.js 按 type 字段路由到对应 Unity 接收方法
               └─► WaterWallBridge（等 C# 脚本）刷新场景
```

**关键点：** 后端只需调用 REST API，`state_server.py` 会自动将其转换为 WebSocket 广播给所有已连接前端；后端无需直接操作 WebSocket。

## 三、各接口详细说明

### 3.1 工况状态切换

**POST /api/state**

```
{
  "state": 2,
  "component": "water_wall",
  "detail": "泄漏检测",
  "confidence": 0.85,
  "source": "prediction_model"
}
```

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `state` | int | ✅ | 状态码，见下表 |
| `component` | string | — | 组件标识（默认 "water_wall"） |
| `detail` | string | — | 状态详情描述 |
| `confidence` | float | — | 置信度 0~1（默认 1.0） |
| `source` | string | — | 数据来源标识（默认 "manual"） |

**状态码定义：**

| 状态码 | 名称 | 场景效果 |
|--------|------|---------|
| 0 | 正常工况 | 恢复原始材质，清除所有特效 |
| 1 | 过热预警 | 黄色脉冲高亮 |
| 2 | 泄漏 | 红色快速脉冲 + 粒子特效 |
| 3 | 爆管 | 深红脉冲 + 红色着色 + 相机震动 |

> 相同状态重复发送不会重复触发（去重）。
> 状态码 4 为预留（管道热力图），当前由场景内按钮手动触发。

**Python 示例：**

```python
import requests
requests.post("http://localhost:8770/api/state", json={
    "state": 2, "detail": "泄漏检测", "source": "prediction_model"
})
```

### 3.2 图表数据

**POST /api/chart**

```json
{
  "chart_type": "temperature",
  "x_labels": ["T-10","T-9","T-8","T-7","T-6","T-5","T-4","T-3","T-2","T-1",
                "T1","T2","T3","T4","T5","T6","T7","T8","T9","T10"],
  "actual_values": [430.1, 432.3, 438.5, 441.0, 445.2, 448.0, 450.1, 452.3, 448.9, 446.2],
  "predicted_values": [429.8, 431.9, 437.2, 440.1, 444.5, 448.0, 449.5, 451.8, 448.2, 445.9,
                        460.2, 462.5, 458.0, 455.3, 450.1, 448.0, 445.5, 442.0, 440.2, 438.5],
  "source": "prediction_model"
}
```

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `chart_type` | string | — | 图表类型标识（默认 "temperature"） |
| `x_labels` | array | ✅ | X 轴标签，长度 = 2N |
| `actual_values` | array | ✅ | 实际值，长度 = N（历史） |
| `predicted_values` | array | ✅ | 预测值，长度 = 2N（前 N 历史 + 后 N 未来） |
| `source` | string | — | 数据来源标识 |

> ⚠ **数组长度**：actual = N，predicted = 2N，x_labels = 2N。通常 N=10。
>
> ⚠ **蒸汽量联动**：actual_values 最后一项会被自动提取为当前蒸汽量，联动管道材质透明度。
>
> ⚠ **命名约定**：REST 请求用 snake_case，state_server.py 广播时自动转 camelCase 给前端。

### 3.3 仪表盘数据

**POST /api/gauge**

```json
{
  "airflow": 452.3,
  "temperature": 387.5,
  "pressure": 17.2,
  "source": "sensor_data"
}
```

| 字段 | 类型 | 必需 | 范围 | 说明 |
|------|------|------|------|------|
| `airflow` | float | ✅ | 0~500 | 送风量 (kmol/h) |
| `temperature` | float | ✅ | 0~600 | 温度 (°C) |
| `pressure` | float | ✅ | 0~25 | 压力 (MPa) |
| `source` | string | — | — | 数据来源标识 |

> ⚠ **字段名注意**：仪表盘用 `airflow`（送风量），不是 `steam`。蒸汽量通过图表数据 `actual_values[-1]` 联动，不走仪表盘通道。

### 3.4 故障指令

**POST /api/fault**

```json
{
  "code": 1,
  "detail": "水冷壁超温",
  "source": "monitoring_system"
}
```

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `code` | int | ✅ | 故障代码（0=清除全部, >0=激活对应故障） |
| `detail` | string | — | 故障详情描述 |
| `source` | string | — | 数据来源标识 |

**故障代码规则：**

| 代码 | 效果 |
|------|------|
| 0 | 清除所有故障，恢复原始材质 |
| >0 | 添加故障到报警列表（可多故障并存，不互相覆盖） |

**多故障机制：**
- 先发 code=1 再发 code=2，两个故障同时存在于报警面板
- 每个故障在面板中显示为一行，可单独 ACK 或关闭
- 故障代码需与 Unity Inspector 的 `FaultDisplayManager.faultDefinitions` 数组已预定义，未定义代码会被忽略

### 3.5 问题推送

**POST /api/question**

向后端推送操作问题/确认通知，`state_server.py` 自动通过 WebSocket 广播 `type=question` 给所有前端。Unity 收到后在屏幕中央弹出问题卡片，操作员点击「已知晓」关闭。

```json
{
  "title": "超温确认",
  "content": "水冷壁温度已超过 480°C，请确认是否启动应急降温程序。",
  "severity": "critical",
  "source": "monitoring_system"
}
```

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `title` | string | — | 问题标题（默认 "操作确认"） |
| `content` | string | ✅ | 问题内容/描述 |
| `severity` | string | — | 严重程度：`info` / `warning` / `critical`（默认 `info`） |
| `source` | string | — | 数据来源标识 |

**WebSocket 广播 JSON：**

```json
{
  "type": "question",
  "title": "超温确认",
  "content": "水冷壁温度已超过 480°C，请确认是否启动应急降温程序。",
  "severity": "critical",
  "source": "monitoring_system",
  "timestamp": "2026-08-18T10:00:00"
}
```

**严重程度颜色映射：**

| severity | 顶部色条颜色 | 说明 |
|----------|-------------|------|
| `info` | 青色 | 信息提示 |
| `warning` | 橙色 | 警告确认 |
| `critical` | 红色 | 紧急确认 |

**Python 示例：**

```python
import requests
requests.post("http://localhost:8770/api/question", json={
    "title": "超温确认",
    "content": "水冷壁温度已超过 480°C，请确认是否启动应急降温程序。",
    "severity": "critical",
    "source": "monitoring_system"
})
```

**WebSocket 直接推送示例：**

```python
import json, websockets, asyncio

async def push_question():
    msg = {
        "type": "question",
        "title": "检修提醒",
        "content": "锅炉已连续运行 72 小时，建议安排计划检修。",
        "severity": "info",
        "source": "backend_direct",
        "timestamp": "2026-08-18T12:00:00"
    }
    async with websockets.connect("ws://localhost:8770/ws") as ws:
        await ws.send(json.dumps(msg, ensure_ascii=False))
```

### 3.6 锅炉模拟计算（特殊：前端→后端）

**POST /api/simulate**

这是**前端发起**的接口之一（另有 `/api/calculate_target` 与 `/api/notify/file`，见 §3.7 / §3.8）。Unity 前端发送参数，后端完成热力学计算后通过 WebSocket 广播结果。

**请求 JSON（前端发送）：**

```json
{
  "coal_feed": 130.0,
  "air_flow": 1100.0,
  "water_flow": 950.0,
  "drum_pressure": 17.5,
  "slag_degree": 0.1,
  "source": "boiler_sim_panel"
}
```

| 字段 | 类型 | 必需 | 范围 | 说明 |
|------|------|------|------|------|
| `coal_feed` | float | ✅ | 60~180 | 给煤量 (t/h) |
| `air_flow` | float | ✅ | 600~1800 | 送风量 (km³/h) |
| `water_flow` | float | ✅ | 400~1100 | 给水流量 (t/h) |
| `drum_pressure` | float | ✅ | 12~20 | 汽包压力 (MPa) |
| `slag_degree` | float | ✅ | 0~0.8 | 结渣程度 |
| `source` | string | — | — | 数据来源标识 |

**后端广播结果 JSON（同时发给 Unity）：**

```json
{
  "type": "simResult",
  "steam_output": 1085.3,
  "wall_temp": 452.1,
  "state_code": 0,
  "state_name": "正常",
  "parameters": {},
  "source": "boiler_sim_panel",
  "timestamp": "2026-07-29T10:00:00"
}
```

> **启用条件**：需在 `BoilerSimulatorPanel` Inspector 中勾选 `useBackendCalculation`。关闭时前端本地公式计算结果，行为一致。

**Unity 解析**：`WaterWallBridge.ReceiveSimResult(json)` → `BoilerSimulatorPanel.ReceiveSimResult(json)` → 提取 `steam_output` / `wall_temp` / `state_code` → 更新界面 + 应用到场景。

### 3.7 目标蒸汽量计算（前端→后端）

**POST /api/calculate_target**

用户在锅炉模拟面板输入初始工况参数后点击「开始计算」，前端将参数发送到后端计算目标蒸汽量。后端复用 `/api/simulate` 相同的热力学公式，将结果作为「目标值」返回并广播。前端随后让用户调节参数逼近该目标，偏差 < 2% 时弹出「已达到预期」提示。

**请求 JSON**（与 `/api/simulate` 完全一致）：

```json
{
  "coal_feed": 130.0,
  "air_flow": 1100.0,
  "water_flow": 950.0,
  "drum_pressure": 17.5,
  "slag_degree": 0.1,
  "source": "boiler_sim_panel"
}
```

**后端广播结果 JSON**（WebSocket 广播 type=`targetResult`）：

```json
{
  "type": "targetResult",
  "target_steam": 1085.3,
  "wall_temp": 452.1,
  "state_code": 0,
  "state_name": "正常",
  "parameters": { ... },
  "source": "boiler_sim_panel",
  "timestamp": "2026-08-17T10:00:00"
}
```

**HTTP 响应**（同步返回，含推荐参数）：

```json
{
  "status": "ok",
  "target_steam": 1085.3,
  "wall_temp": 452.1,
  "state_code": 0,
  "state_name": "正常",
  "rec_coal_feed": 130.0,
  "rec_air_flow": 927.4,
  "rec_water_flow": 950.0,
  "rec_drum_pressure": 17.5,
  "rec_slag_degree": 0.05
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `target_steam` | float | 目标蒸汽量 (t/h) — 用户需要逼近的值 |
| `wall_temp` | float | 管壁温度 (°C) |
| `state_code` | int | 水冷壁状态码 (0=正常, 1=过热, 2=泄漏, 3=爆管) |
| `state_name` | string | 状态名称 |
| `rec_coal_feed` | float | 推荐给煤量 (t/h) |
| `rec_air_flow` | float | 推荐送风量 (km³/h) |
| `rec_water_flow` | float | 推荐给水流量 (t/h) |
| `rec_drum_pressure` | float | 推荐汽包压力 (MPa) |
| `rec_slag_degree` | float | 推荐结渣程度 |

> **与 `/api/simulate` 的区别**：`/api/calculate_target` 用于获取目标值（仅在点击「开始计算」时调用一次），`/api/simulate` 用于调节参数时实时获取当前蒸汽量（节流 500ms 重复调用）。两者复用相同的热力学计算公式 `run_boiler_simulation()`。

**Unity 路由**：WebSocket 广播 `type=targetResult` → `unity-bridge.js` → `WaterWallBridge.ReceiveTargetResult(json)` → `BoilerSimulatorPanel.ReceiveTargetResult(json)`

> **后端也可主动推送目标**：无需前端先发 POST `/api/calculate_target`，后端可直接通过 WebSocket 广播 `type=targetResult` 消息。Unity 收到后自动设置目标蒸汽量并进入"调节逼近"模式。适用于后端独立计算目标后主动下发场景。

**WebSocket 直接推送示例（Python）：**

```python
import json, websockets, asyncio

async def push_target():
    msg = {
        "type": "targetResult",
        "target_steam": 980.5,
        "wall_temp": 465.0,
        "state_code": 0,
        "state_name": "正常",
        "source": "backend_direct",
        "timestamp": "2026-08-10T12:00:00"
    }
    async with websockets.connect("ws://localhost:8770/ws") as ws:
        await ws.send(json.dumps(msg, ensure_ascii=False))
```

> ⚠ 推送时 `source` 建议设为 `"backend_direct"` 等标识，便于前端区分来源。

### 多组推荐参数与假设说明

`targetResult` 消息支持推送多组推荐参数，每组附带独立的假设说明文字。Unity 前端收到后在右侧"系统推荐参数"面板中显示，操作员可通过"下一个"按钮循环切换查看不同方案及其说明。

**字段约定：**

| 字段 | 说明 |
|------|------|
| `rec_*` | 第 0 组推荐参数 + `rec_notes` 对应说明 |
| `rec1_*` | 第 1 组推荐参数 + `rec1_notes` 对应说明 |
| `rec2_*` ~ `rec4_*` | 第 2~4 组（最多 5 组） |

**WebSocket 推送示例（含多组推荐 + 假设说明）：**

```python
msg = {
    "type": "targetResult",
    "target_steam": 980.5,
    "wall_temp": 465.0,
    "state_code": 0,
    "state_name": "正常",
    # 第 0 组推荐参数
    "rec_coal_feed": 130.0,
    "rec_air_flow": 927.4,
    "rec_water_flow": 950.0,
    "rec_drum_pressure": 17.5,
    "rec_slag_degree": 0.05,
    "rec_notes": "通过降低过量空气系数至1.05提高燃烧效率，同时激进清除结渣，预计可提升蒸汽量",
    # 第 1 组推荐参数
    "rec1_coal_feed": 130.0,
    "rec1_air_flow": 968.6,
    "rec1_water_flow": 950.0,
    "rec1_drum_pressure": 17.5,
    "rec1_slag_degree": 0.06,
    "rec1_notes": "采用较低空燃比1.10，适度降低结渣，在效率与安全性之间取得平衡",
    # 第 2 组...
    "rec2_coal_feed": 130.0,
    "rec2_air_flow": 1009.8,
    "rec2_water_flow": 950.0,
    "rec2_drum_pressure": 17.5,
    "rec2_slag_degree": 0.07,
    "rec2_notes": "标准优化空燃比1.15，降低结渣30%，为推荐基准方案",
    "source": "backend_direct",
    "timestamp": "2026-08-18T12:00:00"
}
```

> ⚠ `rec_notes` / `rec1_notes` 等字段支持 `\n` 换行，Unity 端会自动解析为实际换行显示。每组方案的说明独立，切换方案时同步更新。

### 3.8 截图 / CSV 推送企业微信

**POST /api/notify/file**

Unity 侧一键截图 / 导出 CSV 时，在本地浏览器下载文件**同时**把文件推送企业微信群。

```json
{
  "filename": "锅炉截图_20260729_120000.jpg",
  "base64": "<base64 编码的文件内容>",
  "mimeType": "image/jpeg"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `filename` | string | 文件名（含扩展名） |
| `base64` | string | base64 编码的文件内容（无 data: 前缀） |
| `mimeType` | string | MIME 类型，如 image/jpeg / text/csv |

**后端处理策略：**

| MIME | 处理方式 |
|------|---------|
| `image/*` | 推送为**图片消息**（base64≤2MB 时直发原图，否则降级为文字通知） |
| `text/csv` | 推送为 **markdown 文本**（CSV 内容内联，>3800 字节自动截断） |
| `*/*` | 其余类型均匀推送为文字通知 |

企业微信推送由 `state_server.py` 内置 `_broadcast_wechat()` / `_send_wechat_image()` / `_send_wechat_csv()` 完成（纯标准库 urllib，无额外依赖）。

### 3.9 企业微信机器人配置

多个机器人可同时启用，任一机器接收告警/截图/CSV。配置持久化于 `wechat_config.json`（与服务器脚本同目录）。

**读取 / 写入：**

- `GET /api/wechat/config` → 返回 `{"webhooks":[{...}]}`
- `POST /api/wechat/config` → 整体覆盖保存机器人列表

**POST /api/wechat/config**

```json
{
  "webhooks": [
    { "name": "运行群", "url": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx", "enabled": true },
    { "name": "检修群", "url": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=yyy", "enabled": true }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `webhooks` | array | 机器人列表 |
| `webhooks[].name` | string | 机器人名称（默认 "默认群"） |
| `webhooks[].url` | string | 企业微信群机器人 Webhook |
| `webhooks[].enabled` | bool | 是否启用（默认 true） |

**POST /api/wechat/test** 发送测试消息：

```json
{ "url": "", "name": "测试" }
```

- 填 `url`：只测该机器人
- 留空 `url`：测试所有已启用机器

**网页图形界面**：浏览器访问 `GET /wechat-config`，支持在线增删机器人、保存、测试全部、清空列表，即时生效无需重启。

## 八、WebSocket 客户端消息中继

除了通过 REST API 推送数据外，后端/外部系统也可直接连接 WebSocket 发送消息，服务器会自动中继给所有其他已连接客户端（含 Unity 前端）。

**工作方式：** 任何 WS 客户端发送的含 `type` 字段的 JSON 消息，服务器自动广播给除发送者外的所有客户端。发送 `state` 字段的消息则触发状态更新。

**适用场景：**
- 后端模型直接推送预测结果/推荐参数给 Unity，无需经过 REST API
- 测试面板（`test_panel.html`）向 Unity 推送多组推荐参数
- 多个外部系统同时向 Unity 推送不同类型的数据

**Python WebSocket 直推示例：**

```python
import json, websockets, asyncio

async def push_to_unity():
    async with websockets.connect("ws://localhost:8770/ws") as ws:
        # 推送多组推荐参数 + 假设说明
        msg = {
            "type": "targetResult",
            "target_steam": 980.5,
            "wall_temp": 465.0,
            "state_code": 0,
            "state_name": "正常",
            "rec_coal_feed": 130.0,
            "rec_air_flow": 927.4,
            "rec_water_flow": 950.0,
            "rec_drum_pressure": 17.5,
            "rec_slag_degree": 0.05,
            "rec_notes": "方案1：激进降渣，提高燃烧效率",
            "rec1_coal_feed": 130.0,
            "rec1_air_flow": 968.6,
            "rec1_water_flow": 950.0,
            "rec1_drum_pressure": 17.5,
            "rec1_slag_degree": 0.06,
            "rec1_notes": "方案2：低空燃比，平衡效率与安全",
            "source": "backend_direct",
            "timestamp": "2026-08-18T12:00:00"
        }
        await ws.send(json.dumps(msg, ensure_ascii=False))
```

> ⚠ `broadcast_state(data, exclude=ws)` 确保消息不会回传给发送者，避免循环。
> ⚠ 服务器收到不含 `type` 和 `state` 的消息会忽略。

| C# 调用 | .jslib 函数 | JS 回调 | 说明 |
|---------|------------|---------|------|

## 十、注意事项

### 1. 命名约定
- REST 请求用 **snake_case**（如 `x_labels`、`actual_values`）
- 前后端广播时自动转 **camelCase**（如 `xLabels`、`actualValues`）
- Unity C# 解析的是 **camelCase** 字段
- 若直接通过 WebSocket 发送，需手动使用 camelCase

### 2. Content-Type
所有 POST 必须设置 `Content-Type: application/json`

### 3. 数组长度约束
图表数据：`actual_values` = N，`predicted_values` = 2N，`x_labels` = 2N

### 4. 温度过渡
所有热力图数据收到后温度平滑过渡（约 0.5 秒），非瞬间跳变。推送频率 >2 次/秒会导致过渡队列堆积。

### 5. 故障代码预定义
故障代码需在 Unity Inspector 的 `FaultDisplayManager.faultDefinitions` 数组预定义，未定义会被忽略并输出警告。

### 6. WebGL 特殊注意事项
- WebGL 通过 `unity-bridge.js` 中转，消息必须含正确的 `type` 字段
- Unity 未加载时消息会缓存，加载完成后自动重放
- 前端访问的两个端口（8080 页面 / 8770 WS）都需可达

### 7. 端口
- 状态服务器默认：`8770`
- 前端连接默认：`ws://localhost:8770/ws`（独立模式脚本默认值已对齐）
- 使用 `--port` 可覆盖默认端口

# BoilerMind 实验结果反馈（第一阶段）

**POST `/api/boilermind/experiment-result`**

该接口只负责把已经完成的 BoilerMind `ExperimentResult` 映射到现有 Unity
展示协议，不执行训练、实验、科研判定或控制优化。

- 预测曲线映射为 `chartData` → `ReceiveChartData`。
- 实验摘要映射为 `question` → `ReceiveQuestion`。
- `experiment_valid` 和 `verdict` 分行显示并保持独立语义；实验无效不等于
  假设被否定。
- 失败模型的 `warnings` 和 `failure_reason` 原样保留在摘要中。
- feature intervention 的 control/treatment/delta 当前通过 `question` 文本显示。
- 不映射为 `targetResult`：现有 Unity 将该消息解释为目标蒸汽量和控制参数，
  用它承载科研指标会产生错误语义。
- `source=mock` 的样例会显示 `[MOCK]` 标记。

请求样例见 `tests/mock_experiment_result.json`。成功响应会返回实际广播的
`emitted_types`；有曲线时为 `["chartData", "question"]`，无曲线时仅为
`["question"]`。
