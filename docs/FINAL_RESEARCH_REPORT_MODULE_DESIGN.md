# BoilerMind 最终实验研究报告生成模块设计方案

> 状态：产品决策已确认，待进入实现阶段
> 适用范围：一个用户研究问题、一个主假设及若干子假设、一轮或多轮系统自动实验
> 最终产物：面向用户的唯一《实验研究报告》，输出 Markdown、DOCX、PDF

## 实施状态

- 阶段 A：代码已实现并通过相关自动测试。包括多轮研究契约、累计反馈排序、确定性停止控制、FullPipeline 自动多轮接入、逐轮实验记忆与轨迹，以及由实验观察重新进入正式假设生成门禁的自适应候选扩展；尚未执行依赖真实 LLM/RAG/训练后端的现场 E2E 验收。
- 阶段 B～G：待实现。

## 1. 模块定位

BoilerMind 的最终报告不是实验规划书的另一个名称，也不是实验前生成的计划草稿。

- 《实验规划书》：每轮实验执行前生成，负责说明本轮如何验证假设，是现有规划模块的产物。
- 《实验研究报告》：整个研究任务停止后生成，聚合问题、假设、规划、真实执行、失败与调整、最终结果、图表和真实文献，是本方案要新增的最终成果模块。

最终报告的目标是充分展示 BoilerMind 自动解决科研问题的能力，但正文应以“问题如何被解决”为主，只用适量篇幅讲述系统的自动研究链路。

## 2. 已确认的产品决策

1. 每份报告只对应一个研究问题，但允许多个假设、多轮实验、成功与失败实验共存。
2. 系统自动决定假设、实验、迭代、停止和最终结论，不要求用户审批报告。
3. 研究没有成功解决问题时仍生成正式报告，并如实说明失败、已知边界和后续方向。
4. 关键事实或引用无法验证时，不生成看似可信的正式报告，改为输出报告生成异常说明。
5. 报告采用白底科研风格；中文为主，术语首次出现时给出英文全称和缩写。
6. 中文字体暂定正文宋体、标题黑体；英文、数字和公式使用 Times New Roman。
7. 引用采用 GB/T 7714—2015 顺序编码制，禁止虚构文献或由 LLM 补造元数据。
8. 报告默认包含成果概览、研究故事链、多轮实验过程、真实结果、自动图表和参考文献。
9. Source 自动识别历史实验、已有运行数据等内部依据，并在报告中分别说明来源。
10. 研究停止条件综合目标达成、假设判定、资源上限、最大轮数和连续无改进。
11. 理论推导和模拟结果可以进入报告，但必须与真实实验结果分节并显式标记。
12. 正文只显示关键假设ID和实验ID；完整内部ID链保存在附录和审计包。
13. 正文概述运行成本，附录列出实验轮数、耗时、设备、失败重试等明细。
14. 不添加“AI辅助生成”声明；报告本身以 BoilerMind 项目成果交付。

## 3. 当前代码事实与实现边界

### 3.1 已有且可复用

- `ResearchProblemSpec` 已包含原始问题、研究对象、目标变量、工况、研究目标、成功条件和约束。
- `ScientificHypothesis` 及其质量、机制审查和准入结构可提供候选假设、最终假设和推导依据。
- `ExperimentPlan` 已包含假设关联、目标、候选与基线模型、控制/处理组、指标、确认/证伪标准、数据路径、窗口、预测时距、随机种子和执行后端。
- `ExperimentContract` 可冻结实验ID、问题ID、假设ID、规划ID、数据集哈希、划分、变量、模型、指标和判定条件。
- `ExperimentResult` 已包含逐模型指标、基线指标、锁定测试指标、模型配置、告警、失败原因、运行时间和产物路径。
- `ExperimentAudit` 与 `ScientificResult` 可提供实验有效性和 SUPPORTED/FALSIFIED/INSUFFICIENT_EVIDENCE 等科学判定。
- 实验输出目录中已有真实结果 JSON、逐样本预测 CSV、模型产物和专项审计文件，可作为图表和报告事实的来源。
- `CitationRegistry` 已有文献身份、PDF哈希、人工批准快照、确定性格式化和页码/片段绑定检查的基础。

### 3.2 当前缺失，不能宣称已实现

- 没有统一的最终报告领域模型、报告生成服务或 Markdown/DOCX/PDF 编译流水线。
- `ResearchRun` 没有记录多轮实验的有序链、停止原因、最佳实验、未解决问题和报告状态。
- 当前 `execute_closed_loop()` 只完成单次真实实验、审计、判定、反馈和重新排序，不是自动执行多轮实验直到停止的完整研究循环。
- 现有专项 `REPORT.md` 不是统一报告引擎的产物，字段和生成方式尚未形成稳定契约。
- 还没有从逐样本预测和指标产物自动选择、生成、编号并核验图表的模块。
- 还没有用于报告正文的论断—实验事实绑定，也没有防止 LLM 改写或编造数字的检查器。
- 还没有报告级引用顺序编排、同文献去重、正文引用—文末条目一致性检查。
- 当前 GB/T 格式化器仅覆盖预印本、期刊论文和会议论文，尚未覆盖专著、学位论文、标准、报告、专利、网页等文献类型，也尚未完成完整标准符合性验收。
- 当前正式引用依赖已审核文献快照。报告运行时可以全自动使用已经批准的文献，但不能把未审核记录自动升级为正式引用。

## 4. 目标总流程

```text
用户问题
  -> 问题解析
  -> 历史实验/当前数据/文献证据检索
  -> 候选假设生成与筛选
  -> 每轮《实验规划书》
  -> 实验契约冻结
  -> 系统真实执行
  -> 实验审计与科学判定
  -> 结果写入研究轮次
  -> 判断停止条件
       -> 未停止：提出下一轮假设或修改计划并继续执行
       -> 已停止：冻结 ReportFacts
  -> 选择图表并从真实数据生成
  -> 为允许引用的论断检索已核验文献
  -> 建立 ClaimBinding 和 CitationBinding
  -> LLM 按章节生成叙事草稿
  -> 数字、术语、引用、逻辑和字段质检
  -> 编译 Markdown
  -> 渲染 DOCX
  -> 渲染 PDF
  -> 页面、字体和乱码检查
  -> 正式报告或异常说明
```

## 5. 新增核心领域模型

### 5.1 ResearchRoundRecord

每轮研究必须形成不可丢失的链路：

```json
{
  "round_id": "ROUND-001",
  "round_index": 1,
  "problem_id": "PROBLEM-001",
  "hypothesis_ids": ["H001"],
  "selected_hypothesis_id": "H001",
  "plan_id": "PLAN-H001",
  "experiment_ids": ["EXP-001"],
  "experiment_status": "COMPLETED",
  "audit_status": "PASSED",
  "scientific_verdict": "SUPPORTED",
  "observations": [],
  "lessons": [],
  "next_action": "STOP",
  "started_at": "",
  "completed_at": ""
}
```

### 5.2 ResearchTaskSummary

```json
{
  "run_id": "RUN-001",
  "problem_id": "PROBLEM-001",
  "round_ids": ["ROUND-001", "ROUND-002"],
  "primary_hypothesis_id": "H002",
  "best_experiment_id": "EXP-002",
  "final_verdict": "SUPPORTED",
  "problem_resolution_status": "SOLVED",
  "stop_reason": "TARGET_METRIC_REACHED",
  "remaining_uncertainties": [],
  "total_runtime_seconds": 0,
  "completed_at": ""
}
```

`problem_resolution_status` 至少支持：

- `SOLVED`
- `PARTIALLY_SOLVED`
- `NOT_SOLVED`
- `INSUFFICIENT_EVIDENCE`
- `EXECUTION_BLOCKED`

### 5.3 ReportFacts

这是报告生成器唯一允许使用的事实入口。它聚合但不覆盖原始记录：

- 问题事实；
- Source历史依据数据；
- Target实际实验数据；
- 候选和最终假设；
- 每轮实验规划；
- 实际实验契约；
- 真实执行结果；
- 审计与科学判定；
- 研究停止原因；
- 图表数据引用；
- 文献引用绑定；
- 成本与环境信息；
- 缺失字段和冲突项。

`ReportFacts` 生成后计算 SHA-256 并冻结。报告正文中的数字必须能定位到其事实路径和来源文件。

### 5.4 ReportManifest

记录最终报告版本、输入事实哈希、图表、引用、输出文件和质量检查结果。

## 7. 必需标准字段

最终报告必须明确包含并能追溯以下字段：

- 待研究问题（Problem Statement）
- 解决思路（Rationale）
- 必要的技术手段（Technical Details）
- 数据集（Datasets）
- Source
- Target
- 标题（Paper Title）
- 摘要（Paper Abstract）
- 方法论（Methods）
- 实验设计（Experiments）
- 基线（Baselines）
- 评估指标（Metrics）
- 实验结果（Results）
- 参考论文（References）

缺失处理分级：

- P0：事实真实性、数据集身份、实验ID链、结果、引用身份等；缺失则阻止正式报告。
- P1：复现质量、运行环境、重复实验统计等；缺失则降级结论并在报告中说明。
- P2：增强展示的字段；缺失不阻止报告，只是不生成相关内容或图表。

## 8. 报告叙事规则

正文遵循：

```text
具体问题
 -> 已知限制和证据
 -> 历史实验启示
 -> 可验证假设
 -> 实验设计
 -> 本轮真实结果
 -> 由结果触发的下一轮调整
 -> 多轮综合判断
 -> 最终解决状态和适用边界
```

LLM 可以组织叙事、解释逻辑、生成标题摘要和讨论，但禁止：

- 创造、修改或四舍五入到改变含义的实验数字；
- 将计划写成实际执行；
- 将预期、模拟、TEST_ONLY或文献结果写成本项目真实结果；
- 猜测数据集、模型、参数、失败原因或文献字段；
- 在缺少统计依据时使用“显著提升”“证明”“普遍有效”等措辞；
- 将实验完成后检索到的相似方法虚构成实验设计的因果来源。

## 9. 图表系统

### 9.1 必需图表或表格

- 问题—假设—实验—结论链路图；
- 多轮实验时间线；
- 数据集信息表；
- 模型、基线和超参数表；
- 实验结果汇总表；
- 关键指标对比图。

### 9.2 条件触发图表

- 有逐样本预测：真实值—预测值曲线、散点图、残差图；
- 有重复运行：误差线、箱线图或置信区间图；
- 有消融实验：消融对比图；
- 有多工况：分工况性能图；
- 有训练历史：训练/验证曲线；
- 有超参数搜索：超参数敏感性图；
- 有特征贡献结果：特征重要性图。

每张图必须保存 `figure_manifest`：图号、标题、数据源路径、数据文件哈希、生成器版本、参数、生成时间。没有真实数据时不得用随机数或 LLM 想象补图。

## 10. 真实引用与 GB/T 7714—2015

报告只可使用已经进入正式可引用状态的文献。最小引用记录包括：

- `document_id`
- 题名、作者、年份、文献类型和必要出版字段
- DOI或其他可核验身份
- PDF路径和SHA-256
- 身份核验状态
- 正式引用资格
- 支持的正文论断ID
- 页码、chunk ID和支持片段
- 确定性格式化结果

引用流水线：

```text
报告论断
 -> 在已审核文献中检索
 -> 判断用途：背景/方法/结果对照
 -> 验证文献身份和PDF哈希
 -> 验证页码、片段和论断绑定
 -> 只保留正式可引用记录
 -> 按正文首次出现顺序编号
 -> 确定性生成 GB/T 7714—2015 条目
 -> 检查正文编号与文末条目一一对应
```

报告运行时不要求用户再审批，但只允许使用此前已审核通过且审核快照未失效的文献。无合适文献时允许少引或不引，禁止替换成不相关文献。

## 11. 自动停止规则

停止控制器综合判断：

- 目标指标已达到；
- 主假设已得到充分支持或反驳；
- 已达到最大实验轮数；
- 已达到时间或计算资源预算；
- 连续若干轮没有有效改进；
- 当前能力不足，继续执行没有科学意义；
- 所有剩余候选均不可执行。

无论停止原因如何，都必须记录 `stop_reason`。未解决问题不是系统异常；事实链断裂、结果冲突或无法核验才是报告生成异常。

## 12. 自动质量门禁

正式发布前至少执行：

1. 问题—假设—规划—实验—判定ID链检查；
2. 计划与实际执行差异检查；
3. 数据集路径和哈希检查；
4. 指标口径、单位和方向检查；
5. 锁定测试集未参与模型选择检查；
6. 正文所有数字到 `ReportFacts` 的反向绑定检查；
7. 图表与表格数值一致性检查；
8. 模拟、测试和真实结果标签检查；
9. 文献身份、PDF哈希和正式资格检查；
10. 论断—页码—片段绑定检查；
11. 引用顺序、去重和文末条目一致性检查；
12. 必需字段完整性检查；
13. 专业术语、缩写和单位一致性检查；
14. 过度结论和禁止措辞检查；
15. UTF-8、中文字体、公式、图题、表题和负号检查；
16. DOCX和PDF实际渲染后的页面检查。

## 14. 分阶段实施 TODO

### 阶段 A：研究任务聚合层

- 新增 `ResearchRoundRecord`、`ResearchTaskSummary` 和停止原因枚举。
- 将每轮规划、契约、执行、审计、判定和反馈串成有序记录。
- 扩展当前单实验闭环为受预算和停止规则约束的多轮研究循环。
- 为所有输入和产物保存稳定ID与SHA-256。

验收：一个问题可以连续执行至少两轮，并完整重放每轮为何发生、做了什么、得到什么、为何停止。

### 阶段 B：报告事实层

- 新增 `ReportFacts`、`ReportManifest` 和字段分级规则。
- 从现有契约和产物确定性提取事实。
- 实现数字、单位、模型、指标和产物反向绑定。
- 实现冲突检测和正式报告阻断。

验收：不调用LLM也能生成完整机器可读的研究事实包。

### 阶段 C：图表与表格

- 实现图表选择器和白底科研主题。
- 从逐样本预测、指标、训练历史和多轮记录生成图表。
- 生成图表清单、数据源哈希和图表质检结果。

验收：图表中的抽样数值与源CSV/JSON一致，中文、英文、负号和单位无乱码。

### 阶段 D：引用集成

- 定义报告级 `ClaimBinding` 和 `CitationBinding`。
- 接入已审核本地RAG，不允许未批准文献进入正式报告。
- 扩展并测试 GB/T 7714—2015 文献类型。
- 实现首次出现编号、去重、删除后重排和文末一致性检查。

验收：虚构DOI、恶意域名、缺失PDF、哈希变化、错误页码和无支持片段均被拒绝。

### 阶段 E：章节生成与逻辑检查

- 按章节分别生成，禁止一次提示词直接生成整篇报告。
- 为每章提供可用事实白名单和论断输出结构。
- 实现跨章节术语、数字、结论和引用一致性检查。
- 实现项目成果型研究故事链。

验收：LLM无法在事实包之外新增实验数字或正式引用。

### 阶段 F：Markdown、DOCX和PDF

- Markdown作为规范中间稿。
- DOCX应用统一标题、正文、表格、图题、表题和参考文献样式。
- PDF由受控链路从DOCX或统一排版源导出。
- 实际渲染检查页面、字体、目录、分页、图表和乱码。

验收：三种格式的章节、数字、图表编号和引用完全一致。

### 阶段 G：前后端接入

- 后端在研究任务停止后自动触发报告流水线。
- 前端展示报告生成状态、失败原因和最终下载入口。
- 提供成果概览、Markdown预览、DOCX和PDF下载。
- 不增加人工批准步骤，但清晰显示报告是否通过自动质量门禁。

验收：用户只需提出问题，系统完成研究后自动返回最终报告或明确的异常说明。

## 15. 第一版完成标准

第一版不得只以“文件生成成功”为完成。必须满足：

- 使用至少一个真实研究问题和真实实验结果；
- 能聚合多轮或明确验证单轮结构可扩展到多轮；
- 结果数字与原始JSON/CSV一致；
- 至少生成成果概览、结果表、关键指标图和预测/残差图；
- 至少有一条通过身份、PDF和论断绑定检查的真实引用；
- 参考文献由确定性 GB/T 7714—2015 格式化器生成；
- Markdown、DOCX和PDF内容一致；
- PDF实际渲染后中文、英文、数字、公式和图表无乱码；
- 研究未成功时能如实生成未解决报告；
- 事实或引用不可信时能阻止正式发布。
